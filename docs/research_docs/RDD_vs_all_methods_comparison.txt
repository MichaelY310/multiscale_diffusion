RDD 核心数学回顾
================================================================================

前向 SDE:
  dx = [-½β(t)x + γ·f(x_0,t)] dt + √β(t) dW
  其中 f(x_0, t) = √ᾱ_t · κ(t) · d,  d = UP(DOWN(x_0)) - x_0

离散前向:
  q(x_t|x_0) = N(√ᾱ_t·x_0 + √ᾱ_t·κ(t)·d,  (1-ᾱ_t)I)
  κ(t) = (t_global - T_c) / (T_{c+1} - T_c)  ∈ [0,1] 线性增长

预测目标:
  ε̃ = ε + √(ᾱ_t/(1-ᾱ_t)) · κ(t) · d

后验:
  q(x_{t-1}|x_t, x_0) 仍为高斯，均值多一项 posterior_mean_coef_drift · d

DPM-Solver 修正:
  x_{t-1} = standard_dpm_step(x_t) + √ᾱ_{t-1} · (κ(t-1) - κ(t)) · d / (T_{c+1}-T_c)

工程实现:
  文件: diffusion/gaussian_diffusion_with_drift.py
  q_sample: 第 245-272 行
  训练 target ε̃: 第 991-997 行
  后验 drift 修正: 第 285-287 行
  DPM-Solver: 第 1310-1553 行
  采样阶段过渡: RDD_sample.py 第 147-158 行 (noise_filling_upsample)

方法 1: Relay Diffusion (ICLR 2024)
================================================================================

━━━ 数学层面对比 ━━━

Relay 的前向过程 (Stage 2, Blurring Diffusion):
  x_t = Σ_f [α(f,t)·X̂_0(f)]·DCT_basis(f) + σ(t)·(ε + s_block·ε_block)
  其中 α(f,t) = exp(-|f|²·σ_blur²(t)/2)·(1-δ) + δ,  σ_blur(t) = σ_max·sin(t·π/2)²

  展开后: x_t = DCTBlur(x_0, σ_blur(t)) + σ(t)·noise_combined

对比 RDD:
  RDD:   x_t = √ᾱ_t · (x_0 + κ(t)·d) + √(1-ᾱ_t) · ε
  Relay: x_t = α(f,t)·x̂_0(f) + σ(t)·ε_combined

数学本质差异:
  1. RDD 的 drift 是空间域的线性修正: x_0 → x_0 + κ(t)·(blur(x_0)-x_0)
     等效于对 x_0 做时间依赖的加权模糊: x_0 + κ(t)·d = (1-κ(t))·x_0 + κ(t)·blur(x_0)
     即 x_t 的均值在 x_0 和 blur(x_0) 之间线性插值

  2. Relay 的模糊是频域乘法衰减: 每个 DCT 频率 f 独立按 exp(-|f|²·t) 衰减
     高频衰减更快,低频衰减更慢

  3. 关键联系: 如果令 RDD 的 d = blur(x_0) - x_0, 则
     RDD 的均值 = √ᾱ_t · [(1-κ(t))·x_0 + κ(t)·blur(x_0)]
     这等效于一种"线性插值式模糊"——而 Relay 是"指数衰减式模糊"
     两者都实现了"随时间逐渐丢失高频"，但 RDD 是线性过渡，Relay 是指数过渡

  4. 噪声差异: RDD 用标准各向同性高斯; Relay 额外加了 Block Noise (空间 4x4 相关)

后验差异:
  RDD: q(x_{t-1}|x_t,x_0) 闭式高斯, 均值有解析修正项 → 可用 DPM-Solver
  Relay: 由于 DCT 域频率相关衰减, 后验不是简单的各向同性高斯 → 需自定义 DCT 采样器

━━━ 工程实现/架构对比 ━━━

| 维度              | Relay Diffusion                        | RDD                                    |
|-------------------|----------------------------------------|----------------------------------------|
| 框架              | EDM (σ参数化, VE-SDE 风格)             | DDPM (离散β schedule, VP-SDE)          |
| 网络              | DhariwalUNet (ADM, conv-based)         | DiT (Transformer-based)                |
| 输入空间          | 像素空间 (无VAE)                       | VAE latent 空间                        |
| 模型数量          | 2个独立 UNet (Stage1 + Stage2)         | 1-3个 DiT (multistage) 或 1个 (unified)|
| 梯度累积          | batch_gpu=8, 累积64轮→全局4096         | 无累积, 全局256                        |
| 时间条件          | σ (连续, log-normal采样)               | 离散 t ∈ [0, T_stage]                  |
| 预条件化          | c_skip, c_out, c_in, c_noise (EDM式)  | 无显式预条件 (直接预测 ε̃)             |
| 损失权重          | (σ²+σ_d²)/(σ·σ_d)², clamp≤100000      | 均匀 (或可选 importance sampling)      |
| 阶段过渡          | 双线性上采样 + truncated σ=0.9 开始    | nearest上采样 + q_sample 加噪          |
| 混合精度          | FP16                                   | FP32 (或 BF16)                         |
| EMA               | ema=50K images                         | 标准 EMA (0.9999)                      |

━━━ RDD 可借鉴的具体实现 ━━━

1. Block Noise (blurring.py 143-158行):
   实现: g_noise.roll(shifts=(px,py)) 循环累加 / block_size 归一化
   借鉴方式: 在 RDD 的 noise_filling_upsample 中, 将纯高斯噪声替换为
             gaussian + block_scale * block_noise, 可能改善阶段过渡的低频连续性

2. 大 batch + 梯度累积:
   Relay 用 batch_gpu=8 累积 64 轮达到全局 4096
   RDD 当前全局 256, 可以用同样策略增大到 1024-2048

3. EDM 损失权重:
   Relay 的 w(σ) = (σ²+0.25)/(σ·0.5)² 在低噪声时给更大权重
   RDD 可以实验类似的 timestep-dependent loss weighting

━━━ 该方法优势(RDD劣势) ━━━
- 频域操作有明确的物理含义(每个 DCT 系数独立控制)
- Block Noise 比纯高斯更好地模拟了"低分辨率→高分辨率"引入的结构化误差
- 大 batch(4096) 训练更稳定/收敛更快
- 像素空间操作避免了 VAE 重建误差

━━━ 该方法劣势(RDD优势) ━━━
- 两个独立模型分别训练, 总参数量是 RDD 的 2-3 倍
- DCT 域自定义采样器复杂度高, 无法用 DPM-Solver 加速
- 推理需 Stage1(256步) + Stage2(200步) = 456步; RDD 用 DPM-Solver 10-50步
- 无闭式后验, 采样数学不够优雅
- 阶段间硬切换(64→256), 信息传递断裂

━━━ RDD 弥补策略 ━━━
1. [低工作量] 在 noise_filling 中加 Block Noise 消融实验
2. [低工作量] 做频域分析: 画 RDD 在不同 t 步的 DCT 功率谱, 证明
   drift 项确实导致了高频逐渐丢失 → 与 Relay 的模糊扩散本质相同
3. [中工作量] 增大 batch size (梯度累积)
4. [论文写作] 直接对比: RDD 10步 DPM-Solver vs Relay 456步, 计算量/质量对比

方法 2: LapFlow (ICLR 2026)
================================================================================

━━━ 数学层面对比 ━━━

LapFlow 的前向路径 (3级, time_segments=[0.33, 0.67]):
  定义 Laplacian 金字塔:
    L₀ = x - UP(DOWN(x))     (高频残差, 32x32 latent)
    L₁ = DOWN(x) - UP(DOWN²(x))  (中频残差, 16x16 latent)
    L₂ = DOWN²(x)            (低频基础, 8x8 latent)
  
  对每个 scale i, 在对应时间段 [T_i, 1] 内做线性 Flow Matching:
    x_t^(i) = α_i(t) · L_i + σ(t) · ε_i
    其中 α_i(t) = (t - T_i) / (1 - T_i),  σ(t) = 1 - t
    
  预测目标: u_i = dα_i/dt · L_i + dσ/dt · ε_i = L_i/(1-T_i) - ε_i

对比 RDD:
  RDD 的 d = UP(DOWN(x_0)) - x_0 = -L₀ (取反的高频残差!)
  所以 RDD 的前向均值 = √ᾱ_t · (x_0 + κ(t)·d) = √ᾱ_t · (x_0 - κ(t)·L₀)
  即 RDD 在前向过程中逐渐"减掉"高频残差 → 使 t→T 时趋向低分辨率版本

  LapFlow 则是将 x 拆成 L₀, L₁, L₂ 三个独立成分, 每个成分独立做 FM
  
数学等价性分析:
  如果 RDD 只有一级 drift (d = blur(x) - x = -L₀), 则:
    RDD 在 t=T_c 时: 均值 = √ᾱ_{T_c} · (x_0 - L₀) = √ᾱ_{T_c} · blur(x_0)
    即 RDD 在阶段末尾生成的是"x_0 的低频版本 + 噪声"
    
  对比 LapFlow:
    在 t=0.33 时: Scale 2 已完成, 输出 L₂ (最低频)
    在 t=0.67 时: Scale 1 完成, 输出 L₂ + UP(L₁) (低+中频)
    在 t=1.0 时: Scale 0 完成, 输出 L₂ + UP(L₁) + UP²(L₀) (全频)

  关键区别:
  - LapFlow 在不同维度空间操作 (L₀是32x32, L₂是8x8), 需要不同大小的tensor
  - RDD 全程在同一维度空间 (32x32), 通过 drift 隐式实现频率分离
  - LapFlow 各 scale 可并行 (causal mask 允许), RDD 必须串行 (Markov依赖)

速度场 vs 噪声预测:
  LapFlow: v_pred ≈ u = L_i/(1-T_i) - ε_i  (预测方向导数)
  RDD:     ε̃_pred = ε + √(ᾱ/(1-ᾱ))·κ(t)·d  (预测修正噪声)
  
  两者可以互相转换:
    RDD 如果用 v-prediction: v = α'(t)·x_0 + σ'(t)·ε = ...包含d项...
    但由于 RDD 在 DDPM 框架下, v-prediction 不如 ε-prediction 与 DPM-Solver 配合好

━━━ 工程实现/架构对比 ━━━

| 维度              | LapFlow                                | RDD                                    |
|-------------------|----------------------------------------|----------------------------------------|
| 框架              | Flow Matching (ODE, t∈[0,1])           | DDPM (SDE, t∈[0,T], 离散)             |
| 网络              | MultiScaleDiT (MoT)                    | DiT (plain) 或 DiTMultiRes (unified)   |
| 多尺度输入        | 各scale独立patchify→不同token数         | 统一32x32 latent, 各阶段同输入         |
| 时间条件          | 连续 t∈[0,1]                           | 离散 t∈[0, stage_length]               |
| 注意力机制        | 全局attention + causal mask             | 标准全局attention (无mask)             |
| 参数共享方式      | MoT: 共享attention + 独立MLP/LN/QKV    | 完全共享 (unified) 或完全独立 (multi)  |
| 训练时scale选择   | 每iter随机选一个scale_selector          | 每iter固定一个stage (或round-robin)    |
| ODE solver        | dopri5/euler (adaptive/fixed)           | DPM-Solver 1-2阶                       |
| 采样并行性        | causal mask允许部分并行                  | 严格串行 (先8x8,再16x16,再32x32)      |
| loss              | Σ_i MSE(v_pred[i], u[i]) * w_i         | MSE(ε̃_pred, ε̃)                        |
| 梯度裁剪          | grad_clip_norm=1.0                      | 无                                     |
| 学习率调度        | CosineAnnealing                         | 恒定                                   |

━━━ 代码相似性详解 ━━━

1. 时间段划分 (最核心的相似点):
   LapFlow: time_segments = [0.33, 0.67] → [0, 0.33, 0.67, 1.0]
   RDD:     stage_lengths = [300, 300, 400] → 全局时间 [0, 300, 600, 1000]
   归一化后: RDD = [0, 0.3, 0.6, 1.0] ← 几乎相同！
   
   代码位置:
   LapFlow: feb12_train_ours.py 第392-411行 (scale_selector → 时间范围映射)
   RDD:     train_RDD_imagenet256.py 第192-206行 (stage_lengths → T_c边界)

2. 从粗到细生成:
   LapFlow: 先生成 L₂(8x8), 再 L₁(16x16 条件于L₂), 再 L₀(32x32 条件于L₁+L₂)
   RDD:     先在 [600,1000] 生成 8x8, 上采样加噪到16x16, 在 [300,600] 生成16x16...
   本质相同: 都是先低频后高频的渐进式生成

3. 可直接复用的代码:
   - Causal attention mask (MultiScaleDiT.py 156-164行):
     RDD的unified模型可以加causal mask让不同阶段的token有依赖关系
   - per-scale loss weight (feb12_train_ours.py 602-603行):
     RDD可以给不同stage设不同loss权重(目前是均匀的)
   - 梯度裁剪 + LR cosine decay (feb12_train_ours.py 491行):
     RDD目前没有梯度裁剪和LR decay, 可以加

━━━ 该方法优势(RDD劣势) ━━━
- MoT 让各 scale 有专属的投影/MLP, 但共享 attention, 参数效率更高
- Causal mask 从理论上保证了因果依赖的正确性
- 部分并行采样加速推理 (所有scale同时前向, 只是mask限制了信息流向)
- 各 scale 独立 loss weight 可精细调优
- Flow Matching 训练通常比 DDPM 更稳定 (方差更低)

━━━ 该方法劣势(RDD优势) ━━━
- ODE 采样无法使用 DPM-Solver (需要高阶 solver 时效率不如 DPM-Solver)
- 需要显式 Laplacian 分解作为预处理 (额外计算和假设)
- 各 scale 的 tensor 维度不同, 实现更复杂
- 训练报告不稳定, 需要 careful hyperparameter tuning
- 无闭式后验, 无法做精确的概率推断

━━━ RDD 弥补策略 ━━━
1. [高优先] 实验 RDD 的 Flow Matching 版本作为 Appendix:
   路径: x_t = (1-t)·(x_0 + κ(t)·d) + t·ε
   目标: u = d/dt[x_t] 包含 drift 导数项
   目的: 建立 RDD-DDPM 和 FM 的理论桥梁, 证明 RDD 的思想框架无关

2. [中优先] 在 unified 模型中加入 per-stage loss weighting

3. [低优先] 考虑在 unified DiT 中加 causal mask
   但需权衡: causal mask 会阻止高分辨率阶段利用低分辨率token, 
   而 RDD 的 drift 已经隐式编码了这个信息, 可能反而有害

4. [论文写作] 明确说明: LapFlow 的 time_segments 等效于 RDD 的 stage_lengths,
   但 RDD 在 DDPM 框架下保持了闭式后验+DPM-Solver兼容, 是更统一的方案


================================================================================
方法 3: DiMR (NeurIPS 2024)  -- FID=1.70, 当前最强
================================================================================

━━━ 数学层面对比 ━━━

DiMR 的前向过程:
  完全标准 VP-SDE, Stable Diffusion beta schedule:
  β_t = (β_0^0.5 + (β_1^0.5-β_0^0.5)·t/T)², β_0=0.00085, β_1=0.012
  x_t = √ᾱ_t · x_0 + √(1-ᾱ_t) · ε    (无任何修改!)

DiMR 的多尺度目标:
  对于 2R 配置 (2个Stage):
    target_32x32 = ε                    (原始噪声, 32x32)
    target_16x16 = AvgPool_2x2(ε) / 2  (2x2均值池化, 除以2做scale correction)
  
  损失: L = 0.25 · MSE(pred_16, target_16) + 1.0 · MSE(pred_32, target_32)

对比 RDD:
  RDD 的多尺度信息编码在 target 中:
    target = ε̃ = ε + √(ᾱ/(1-ᾱ)) · κ(t) · d
    其中 d = UP(DOWN(x_0)) - x_0 包含了"低分辨率缺失的高频信息"

  数学联系:
    DiMR 让网络在 16x16 预测 AvgPool(ε) → 等效于让网络"学习噪声的低频结构"
    RDD  让网络预测 ε + drift_correction → 等效于让网络"学习噪声 + 分辨率先验"
    
    两者都在"告诉网络低分辨率信息", 但方式不同:
    - DiMR: 通过架构(多Stage)和目标(池化后的ε)显式分解
    - RDD:  通过修改SDE(drift)和目标(ε̃)隐式编码

时间条件差异:
  DiMR: log_snr = (n/1000)*8 - 4, 通过 Time-Dependent Parameter (TDP) 注入
        TDP: result = sigmoid(a)·param0 + (1-sigmoid(a))·param1
        其中 a = (log_snr/4)·weight + bias
  RDD:  离散 t, 通过标准 DiT 的 sinusoidal + MLP 嵌入

━━━ 工程实现/架构对比 ━━━

| 维度              | DiMR                                   | RDD                                    |
|-------------------|----------------------------------------|----------------------------------------|
| 扩散过程          | 完全标准 VP-SDE (不改!)                | 修改 VP-SDE (加 drift)                 |
| 网络架构          | MRModel: Transformer(16x16) + ConvNeXt(32x32) | DiT (纯 Transformer)             |
| 多分辨率处理      | 架构内部: stride=2卷积降分辨率          | 前向过程: drift编码分辨率              |
| Stage间信息传递   | PixelShuffle上采样 + skip connection    | drift项隐式传递                        |
| 时间条件方式      | TDP: sigmoid插值两组参数               | Sinusoidal + MLP                       |
| 预测输出          | 多个head: [eps_16x16, eps_32x32]       | 单个head: eps_tilde_32x32              |
| DPM-Solver        | predict_x0=True, 250步                 | predict_eps + drift修正, 10-50步       |
| 模型参数量        | 505M (XL) / 1.06B (G)                 | ~675M (XL/2)                           |
| Optimizer         | AdamW(β=(0.99,0.99), wd=0.03)          | AdamW(β=(0.9,0.999), wd=0)            |
| 训练设备          | 16 GPU, 2 nodes                        | 8 GPU, 1 node                          |
| 总训练步数        | 1,000,000                              | 目标700,000                            |
| Batch size        | 1024                                   | 256                                    |
| CFG               | p_uncond=0.1, scale=1.5(eval时)        | p_uncond=0.1                           |

━━━ 代码相似性详解 ━━━

1. DPM-Solver 集成:
   DiMR: model_fn → eps_pred → predict_x0 → DPM-Solver更新
         dpm_solver.py, predict_x0=True
   RDD:  model_fn → ε̃_pred → 反推pure_eps → DPM-Solver更新 + drift_step修正
         gaussian_diffusion_with_drift.py 1310-1553行
   
   关键差异: DiMR 直接用标准DPM-Solver; RDD 在每一步额外加 drift修正项
   
2. 多尺度目标构造:
   DiMR: even_multi_scale_targets() → F.conv2d(eps, ones/KS, stride=KS, groups=C)
         即对 epsilon 做均值池化得到低分辨率版本 (sde.py 313-327行)
   RDD:  ε̃ = ε + correction (gaussian_diffusion_with_drift.py 991-997行)
         RDD 不是池化 epsilon, 而是在 epsilon 上叠加 drift 修正
   
   可融合思路: RDD 也输出多个head, 一个预测 ε̃(32x32), 另一个预测 pool(ε̃)(16x16)
              作为辅助损失, 类似 DiMR 的多尺度目标

3. 架构可借鉴:
   - ConvNeXt block 处理高分辨率 (比纯attention更高效):
     DiMR 在 32x32 stage 用 ConvNeXt 而非 Transformer → 节省计算
     RDD 可以在高分辨率 stage 也用 ConvNeXt 替代部分 attention 层
   - TDP (Time-Dependent Parameter):
     比 sinusoidal embedding 更精细的时间条件注入方式
     RDD 可以采用类似方法

━━━ 该方法优势(RDD劣势) ━━━
- FID=1.70, 绝对指标最强; 架构设计成熟, 工程优化到位
- Transformer(低分辨率) + ConvNeXt(高分辨率) 混合架构效率高
- TDP 时间条件注入比 MLP embedding 更精细
- PixelShuffle 特征传递高效且无信息损失
- AdamW(β2=0.99) + wd=0.03 的超参组合经过充分验证
- Batch 1024 + 16GPU 训练充分, 结果可信

━━━ 该方法劣势(RDD优势) ━━━
- 完全不改前向过程 → 没有利用"分辨率结构"作为归纳偏置
  在同等训练步数下, RDD 的 drift 提供了额外的结构先验, 可能收敛更快
- 需要设计 multi_scale_targets 的降采样 kernel, 且 scale_correction 是个 heuristic
- 1M步 × batch1024 × 16GPU = 巨大计算量; RDD 如果能在 200-700K步达到类似效果, 
  则训练效率更高 (drift 相当于免费的 data augmentation)
- 多 head 输出增加了参数量和复杂度

━━━ RDD 弥补策略 ━━━
1. [高优先] 训练到 700K 步后直接对比: RDD-XL/2 @ 700K vs DiMR-XL @ 700K
   如果 RDD 在相同步数下 FID 更低, 则证明 drift 带来了收敛加速

2. [中优先] DiMR 架构 + RDD drift 融合实验:
   - 在 DiMR 的 MRModel 中加入 drift: 训练时 target 从 ε 改为 ε̃
   - 这样既有架构优势又有 drift 先验

3. [中优先] 学习 DiMR 的训练超参:
   - AdamW(β2=0.99, wd=0.03)
   - batch 1024
   - warmup 5000 步
   
4. [论文写作] 将 RDD 定位为"与 DiMR 正交的改进":
   DiMR 改架构, RDD 改过程, 两者可以结合


================================================================================
方法 4: DCTdiff (ICML 2025)
================================================================================

━━━ 数学层面对比 ━━━

DCTdiff 的前向过程:
  标准 VP-SDE 但在 DCT 系数空间操作, 且修改了 beta schedule:
  
  β_eff(t) = β(t) + d/dt[log(1 + (S-1)·exp(-∫₀ᵗ β(s)ds))]
  
  展开: 设 A(t) = ∫₀ᵗ β(s)ds, 则
  β_eff(t) = β(t) + (S-1)·exp(-A(t))·(-β(t)) / (1 + (S-1)·exp(-A(t)))
           = β(t) · [1 - (S-1)·exp(-A(t)) / (1 + (S-1)·exp(-A(t)))]
           = β(t) · 1 / (1 + (S-1)·exp(-A(t)))
  
  效果: 有效的 ᾱ_T 被放大, 终端 SNR × S倍

  在 DCT 空间中, 每个频率系数独立加噪:
  x_t(f) = √ᾱ_eff(t) · x_0(f) + √(1-ᾱ_eff(t)) · ε(f)
  
  但所有频率使用相同的 β_eff(t) schedule (全局 SNR_scale=S 是统一的)

对比 RDD:
  RDD 的 drift 在频域的效果:
  设 x_0 的 DCT 分解为 x̂_0(f), 则 d = blur(x_0) - x_0 在频域为:
    d̂(f) = (LP(f) - 1) · x̂_0(f)     (LP是低通滤波器频率响应)
  
  RDD 前向均值在频域:
    μ_t(f) = √ᾱ_t · [1 + κ(t)·(LP(f)-1)] · x̂_0(f)
           = √ᾱ_t · [(1-κ(t)) + κ(t)·LP(f)] · x̂_0(f)
  
  有效 SNR(f,t):
    SNR_RDD(f,t) = ᾱ_t · [(1-κ(t)) + κ(t)·LP(f)]² / (1-ᾱ_t)
  
  对于高频 f (LP(f)≈0): SNR_RDD(f,t) = ᾱ_t·(1-κ(t))² / (1-ᾱ_t)
  对于低频 f (LP(f)≈1): SNR_RDD(f,t) = ᾱ_t / (1-ᾱ_t)  (不变!)
  
  结论: RDD 的 drift 等效于**频率自适应的 SNR 衰减**:
  - 低频 SNR 不变 (被 drift 保护)
  - 高频 SNR 被额外衰减 (1-κ(t))² 倍
  
  而 DCTdiff 的 SNR_scale 是全局统一放大, 不区分频率!
  → RDD 比 DCTdiff 更精细: 频率自适应 vs 全局统一

━━━ 工程实现/架构对比 ━━━

| 维度              | DCTdiff                                | RDD                                    |
|-------------------|----------------------------------------|----------------------------------------|
| 操作空间          | DCT系数空间 (block-wise 2D DCT)        | 像素/latent 空间                       |
| 数据预处理        | RGB→YCbCr→4:2:0→分块→DCT→zigzag→截断   | 标准 VAE encode                        |
| token 形式        | (H/B·W/B, 6·low_freqs) 频率token       | (H/p·W/p, C·p²) patch token           |
| SNR 修正方式      | 全局 SNR_scale 参数 (标量)             | 频率自适应 drift (向量场)              |
| 频率处理          | 显式: zigzag排序+高频截断+频率加权loss  | 隐式: drift自动实现频率自适应          |
| 可扩展性          | 受限于 block_sz 和 token 数            | 自然扩展到任意分辨率                   |
| DPM-Solver        | 使用 (修改了 noise_schedule 中的 beta) | 使用 (加 drift 修正步)                 |
| 网络              | UViT (embed=768, depth=16, heads=12)   | DiT-XL/2                               |
| 验证分辨率        | 仅 64x64                               | 256 (目标 512)                         |

━━━ 该方法优势(RDD劣势) ━━━
- 有"扩散=频谱自回归"的理论分析, 论文理论深度好
- SNR_scale 有闭式最优解: S* = argmin FID (可以grid search)
- DCT 系数的物理含义明确, 便于解释
- 频率加权 loss 有统计学依据 (按标准差归一化)

━━━ 该方法劣势(RDD优势) ━━━
- 全局 SNR_scale 不区分频率, 不如 RDD 的频率自适应精细
- 仅在 64x64 验证, 未 scale 到 256/512
- 数据预处理 (RGB→YCbCr→DCT→zigzag) 复杂, 引入额外假设
- token数 = (H/B)² × 6 × low_freqs, 随分辨率平方增长
- 不能处理连续分辨率变化 (block_sz 固定)

━━━ RDD 弥补策略 ━━━
1. [高优先/论文理论] 推导 RDD drift 在频域的等效 SNR 公式 (上面已给出):
   SNR_RDD(f,t) = ᾱ_t · [(1-κ(t)) + κ(t)·LP(f)]² / (1-ᾱ_t)
   这证明了 RDD 实现了频率自适应的 SNR 调整, 比 DCTdiff 的全局 S 更优

2. [中优先] 频域可视化实验:
   - 对不同 t 步的 x_t 做 DCT, 画功率谱
   - 对比: 标准DDPM、RDD、DCTdiff 的频域SNR曲线
   - 展示 RDD 的高频 SNR 衰减更快 → 符合"先低频后高频"生成

3. [论文写作] 在 Related Work 中引用 DCTdiff 的"扩散=频谱自回归"理论,
   说明 RDD 的 drift 是这一理论的一个优雅实现方式


================================================================================
方法 5: SPEED (Stanford 2025) — Training-free
================================================================================

━━━ 数学层面对比 ━━━

SPEED 的核心公式:
  1. 频谱噪声扩展: x_expanded = IDCT[DCT(x_src) ⊕ t·ε_high]
     低频位置保持源信号,高频位置填入幅度为t的噪声
  
  2. 最优转换时刻 (基于功率谱模型 P(ω) = A·|ω|^(-β)):
     t*(ω) = 1 / (1 + √(δ / (P(ω)·(1 + P(ω) - δ))))
     在 ω = s_i·ω_max (当前尺度的 Nyquist 频率) 处取值作为转换时刻
  
  3. 时间步对齐:
     κ(t, r) = r / (1 + (r-1)·t)
     t̃ = t · κ(t, r)    (对齐后的等效时间)
     x̃ = κ(t, r) · x_expanded   (缩放后的状态)

对比 RDD:
  RDD 的 stage_lengths 决定了各分辨率阶段的时间范围:
    stage_lengths = [300, 300, 400] → 转换点在 t=300/1000=0.3 和 t=600/1000=0.6
  
  SPEED 的理论可以给出最优转换点:
    对于 ImageNet latent (32x32, f=8), 设 Nyquist 频率对应 ω_1=0.5, ω_2=0.25
    用 A=203.6, β=1.915 (FLUX VAE 参数), δ=0.01:
    t*(ω_1) 和 t*(ω_2) 就是最优的阶段边界
    
  RDD 可以直接用 SPEED 公式计算最优 stage_lengths!

RDD 的阶段过渡 vs SPEED 的频谱扩展:
  RDD:   在阶段边界做 noise_filling: x_next = √ᾱ·UP(pred_x0) + √(1-ᾱ)·ε
  SPEED: 在转换时刻做 spectral_expand: x_next = κ·IDCT[DCT(x) ⊕ t·ε_high]
  
  两者都是"将低分辨率状态扩展到高分辨率 + 在高频位置添加噪声"
  区别: RDD 在空间域做 (nearest上采样 + 全频段加噪)
        SPEED 在频域做 (低频保持 + 仅高频加噪) → 更精细

━━━ 该方法优势(RDD劣势) ━━━
- 有数学最优的分辨率调度 (RDD的stage_lengths目前是手动设定)
- kappa 对齐保证分辨率转换后的状态与模型期望一致
- 频域扩展只在高频加噪,保持低频信号 (比RDD的全频段加噪更合理)
- 不需要任何训练

━━━ RDD 弥补策略 ━━━
1. [高优先/低工作量] 用SPEED的功率谱公式计算RDD的最优stage_lengths:
   - 需要: 测量 RDD VAE latent 的功率谱参数 A, β
   - 计算: activation_time(Nyquist_freq_at_each_scale)
   - 得到: 最优的 [T_1, T_2, T_3] 划分

2. [中优先] 改进 noise_filling: 参考SPEED的频谱扩展方式
   当前: x = √ᾱ·UP(x0) + √(1-ᾱ)·ε  (全频段噪声)
   改进: x = √ᾱ·UP(x0) + √(1-ᾱ)·IDCT[0_low ⊕ ε_high]  (仅高频噪声)
   → 保持已生成的低频结构不被噪声破坏

3. [论文写作] 引用SPEED的理论作为RDD设计动机的理论支撑


================================================================================
方法 6: LowDiff (2025)
================================================================================

━━━ 数学层面对比 ━━━

LowDiff (Flow Matching版本) 的前向路径:
  分两个独立的 FM 过程:
  低分辨率 (8x8):  x_t^L = (1-t)·ε_L + t·x_L    (无条件)
  高分辨率 (16x16): x_t^H = (1-t)·ε_H + t·x_H   (条件于 x_L 的去噪结果)
  
  网络输入: 高分辨率时 input = [x_t^H; UP(x_L_denoised)]  (channel concat)
  预测目标: u = dx_t/dt = x - ε  (标准 velocity)

对比 RDD:
  RDD 是单一过程中编码两个分辨率:
  x_t = √ᾱ_t·(x_0 + κ(t)·d) + √(1-ᾱ_t)·ε
  
  LowDiff 是两个独立过程, 通过条件连接:
  Process_L: x_t^L → 完全去噪 → x̂_L
  Process_H: [x_t^H; UP(x̂_L)] → 去噪 → x̂_H
  
  数学差异:
  - RDD: drift 项将 x_L 信息连续注入到同一个 SDE 的均值函数中
  - LowDiff: x_L 信息通过网络输入的 concat channel 注入
  
  等效性分析:
  如果 RDD 在 t>T_c 时 κ(t)=1, 则 x_t 的均值 = √ᾱ_t·blur(x_0)
  等效于"已经生成好低分辨率,在此基础上加噪"
  这与 LowDiff 的 x_t^H | x̂_L 条件生成在直觉上类似
  但 RDD 通过 SDE drift 实现, 有数学上的连续性保证

━━━ 工程实现/架构对比 ━━━

| 维度              | LowDiff                                | RDD                                    |
|-------------------|----------------------------------------|----------------------------------------|
| 多分辨率方式      | avg_pool降采样 + concat条件             | drift修改前向过程                      |
| 条件注入          | channel concatenation                   | SDE drift项 (无显式条件输入)           |
| 网络共享          | 共享层(中间14层) + 专属层(前后各7层)   | 完全共享 (unified) 或完全独立 (multi)  |
| 分辨率标识        | ResEmbedder: 加到time+class embedding   | 通过stage_id隐式区分                   |
| 推理加速          | 低分辨率先做完→高分辨率只做后半段        | DPM-Solver少步数                       |
| 截断采样          | trunc_point=0.3 (低分辨率在30%时停止)  | 各阶段完整采样                         |
| VAE               | VA-VAE f16d32 (16x下采样, 32通道)      | Stable Diffusion VAE (8x, 4通道)       |

━━━ 代码相似性详解 ━━━

1. 层分配策略 (lightningdit.py 457-699行):
   LowDiff: 8x8用中间14层, 16x16用全部28层
   RDD unified: 所有分辨率用同一组所有层
   
   可借鉴: RDD可以让低分辨率阶段只用部分层(节省计算)
           高分辨率阶段用全部层(保证质量)

2. 分辨率嵌入 (ResEmbedder):
   LowDiff: res_embed = MLP(one_hot(res_id))
            final_condition = time_embed + class_embed + res_embed
   RDD:     无显式分辨率标识
   
   可借鉴: 在RDD的unified模型中加res_embed, 告诉模型当前处理哪个阶段

3. 截断采样 (inference.py 310-360行):
   LowDiff: 低分辨率阶段从t=0采样到t=0.3就停止(不完全去噪)
            高分辨率阶段从t=0采样到t=1(完整去噪)
   RDD:     各阶段都完整从T_c采样到T_{c+1}
   
   可借鉴: RDD的低分辨率阶段(8x8)可以在早期停止→节省计算

━━━ 该方法优势(RDD劣势) ━━━
- 推理加速 50-83%: 低分辨率步数少,高分辨率步数多
- 层分配策略计算效率高: 低分辨率用少层
- 架构简单易实现 (共享层+concat就行)
- VA-VAE f16d32 (32通道) 比 SD-VAE (4通道) 重建质量更好

━━━ 该方法劣势(RDD优势) ━━━
- 各分辨率是独立的扩散过程,无数学统一性
- concat条件是"事后补救",不如drift的"内嵌先验"自然
- 低分辨率阶段的结果如果不好,高分辨率无法修正(串行依赖,无修正机制)
  RDD的drift在整个过程中持续修正


================================================================================
方法 7: Pyramid-Flow (ICLR 2025) — 视频
================================================================================

━━━ 数学层面对比 ━━━

Pyramid-Flow 的多阶段 FM:
  3个阶段, stage_range = [0, 1/3, 2/3, 1]:
  
  阶段 i 的 start_point 和 end_point:
    阶段0 (t∈[0,1/3]): start=纯噪声(低分辨率), end=低分辨率clean(但带部分噪声)
    阶段1 (t∈[1/3,2/3]): start=UP(阶段0结果)+renoise, end=中分辨率clean
    阶段2 (t∈[2/3,1]): start=UP(阶段1结果)+renoise, end=高分辨率clean

  每阶段内线性插值: x_t = ratio·start + (1-ratio)·end
  目标: u = start - end

Renoising 的精确公式:
  α = 1 / (√(1 + 1/γ) · (1 - σ_ori) + σ_ori)
  β = α · (1 - σ_ori) / √γ
  latents_new = α · UP(latents_old) + β · block_noise
  
  其中 γ 是超参数,控制 renoising 强度:
  - γ→∞: α→1/(1-σ+σ)=1, β→0, 即不加噪声 (直接上采样)
  - γ→0: α→0, 噪声完全覆盖 (丢失所有信息)

对比 RDD:
  RDD 的阶段过渡 (noise_filling_upsample):
    x_next = √ᾱ_{t_start} · UP(pred_xstart) + √(1-ᾱ_{t_start}) · ε
  
  等效地: α_RDD = √ᾱ_{t_start},  β_RDD = √(1-ᾱ_{t_start})
  这是由下一阶段的起始时间步 t_start 唯一决定的!
  
  Pyramid-Flow 通过额外参数 γ 控制加噪强度;
  RDD 通过 stage_lengths (决定 t_start) 隐式控制加噪强度.
  
  数学联系: 如果 RDD 让 t_start 可调, 等效于 Pyramid-Flow 的 γ

━━━ 该方法优势(RDD劣势) ━━━
- γ 参数提供了阶段过渡的额外自由度
- block_noise (而非纯高斯) 在视觉上更自然
- 支持时空联合金字塔 (视频生成)

━━━ RDD 弥补策略 ━━━
1. [低工作量] 在 noise_filling 中加入可调的 γ 参数
   当前: α = √ᾱ_{t_start}, β = √(1-ᾱ_{t_start})
   改为: α = 1/(√(1+1/γ)·(1-σ)+σ), β = α·(1-σ)/√γ, 其中 σ=1-√ᾱ_{t_start}
   消融不同 γ 值对 FID 的影响

2. [论文写作] 明确论述: RDD 无需 renoising 因为 drift 已经在整个过程中
   持续编码低分辨率信息, 不存在"信息丢失后需要重新注入"的问题


================================================================================
方法 8-12: 简要分析 (SwD / MrFlow / XCube / OctFusion / PDD)
================================================================================

这些方法与 RDD 的数学差异较大(蒸馏/免训练/3D),重点总结可借鉴点:

SwD:
  - boundary划分逻辑与RDD stage_lengths完全同构
  - DMD+GAN+MMD蒸馏损失组合 → RDD future work: 蒸馏加速

MrFlow:
  - direct_sigma_schedule: 精炼时从特定σ开始 → RDD可借鉴用于最后阶段的少步精炼

XCube/OctFusion:
  - v-prediction (v = α'·x_0 + σ'·ε) 可能比 ε-prediction 更稳定
  - self-conditioning (用上一步pred作为条件) → RDD可加入, 文献报告+5-15% FID

PDD:
  - 仅100步离散扩散即可(步数极少) → RDD理论上也不需要1000步,
    如果 drift 提供了足够强的先验, 可以减少 diffusion_steps 到 500 或更少
